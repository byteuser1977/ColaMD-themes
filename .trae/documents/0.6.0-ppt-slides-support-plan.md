# ColaMD-themes 0.6.0 — 2.7.13-rc.2 PPT 样式支持计划

## Context

ColaMD-extend 2.7.13-rc.2（本地 `D:\workspace\Git\ColaMD-extend`，未发布、未提交）新增了**幻灯片版式系统**：`---` 分页 + 页头块 `<!-- slide: cover / kicker / label / chapter -->`、deck 块、页内 `slide-css`/`slide-js`，内置 11 种版式（cover/section/agenda/kpi/timeline/steps/matrix/two-col/figure/quote/closing），版式令牌为 `--slide-*`（约 30 个，`slides.css` 的 `:root` 提供默认值，用户 CSS 在其后加载可覆盖）。

本工具（colamd-themes，当前 0.5.9）需要升级到 0.6.0，提供三件事：

1. **主题可携带 PPT 样式**：提取主题时可选生成 `--slide-*` 自定义区块（默认关闭，`--ppt [serif|sans|mono]` 开启）。
2. **Markdown → PPT Markdown 生成器**：新命令按内容结构自动推断版式，产出符合 rc.2 指令语法的幻灯片文档。
3. **Skill 与规则校验**：更新 colamd-themes skill（并入现有 SKILL.md），新增幻灯片 CSS / Markdown 校验规则。

**已确认的决策**（用户选定）：
- PPT 区块默认关闭，`--ppt` 开启，可选预设 serif/sans/mono
- 平台对接用「能力探测 + 双契约兼容」（2.7.12 与 2.7.13-rc.2 都认），不做本地 file: 依赖
- to-slides 自动推断全部 11 种版式
- PPT 能力并入现有 colamd-themes skill

**关键上游事实**（探索结论）：
- rc.2 `themes/contract.json` 的 liveVariables 仍是 27 个文档契约变量，**不含** `--slide-*`（幻灯片令牌是平行体系，不属于文档契约）→ 校验器不能把 `--slide-*` 当死变量，也不需要进 compat 活变量清单
- rc.2 lib 导出路径（`src/lib/index.ts`）**未引入 slides.css**，`collectExportStyles` 只回填契约活变量 → 经 `buildExportHTML` 的 HTML/PDF 导出仍是文档式排版，幻灯片版式只在应用内放映生效。0.6.0 不承诺导出 PDF 呈现版式，compat 探测 + 提示即可
- 自定义主题 CSS 在应用内加载于 slides.css 之后，`:root { --slide-*: … }` 同权重后到先赢 → 主题 PPT 区块写在 `:root` 即可，不需要 `body.theme-custom`（后者是文档契约死选择器，校验器会拒绝）
- to-slides 的分页语义必须与上游 `slide-directives.ts` 一字不差：`---`（HorizontalRule）归它结束的那页、下一行开新页；frontmatter 排除；代码块里的 `---` 天然不是 HR。用 `@lezer/markdown`（上游同款解析器）保证语义一致

## 实施步骤

### 1. 兼容层：`src/compat.ts`

- `SUPPORTED_CONTRACT = "2.7.12"` 保持，新增 `SUPPORTED_CONTRACTS = ["2.7.12", "2.7.13-rc.2"]`：`getColamdCompat` 的 `exact` 判定改为「契约版本命中任一支持版本」（`contractVersion === "2.7.13-rc.2"` 也不报 drift）
- 新增 `SLIDES_MIN_VERSION = "2.7.13-rc.1"` 与 `slidesSupported: boolean` 探测：
  1. 主判据：安装版本 ≥ 2.7.13-rc.1（简单的版本段比较，处理 `-rc.N` 后缀）
  2. 兜底：`dist/lib/colamd.css` 中含 `--slide-` 或 `.cm-md-page-start` 特征也视为支持
- `formatColamdCompat` 追加幻灯片能力描述（如「幻灯片版式: 支持/不支持（需 ≥2.7.13-rc.1）」）

### 2. 幻灯片令牌与预设：新建 `src/slides.ts`

- `SLIDE_TOKENS: readonly string[]` — rc.2 `slides.css` `:root` 的全部令牌名（--slide-serif / --slide-mono / --slide-title-font / --slide-title-size / --slide-title-weight / --slide-subhead-weight / --slide-title-tracking / --slide-title-line-height / --slide-cover-title-size / --slide-cover-title-line-height / --slide-cover-title-tracking / --slide-section-title-size / --slide-closing-title-size / --slide-lead-size / --slide-kicker-size / --slide-kicker-tracking / --slide-kicker-transform / --slide-chrome-opacity / --slide-chrome-transform / --slide-kpi-number-size / --slide-quote-size / --slide-page-pad-x / --slide-page-top-pad / --slide-page-top-pad-print / --slide-cover-text-align / --slide-cover-lead-inline）
- `SLIDE_PRESETS: Record<"serif"|"sans"|"mono", Record<string, string>>` — 对齐上游内置气质：serif = 上游默认（杂志衬线）；sans = 抄 `body.theme-notion` 覆盖值（无衬线、居中封面、kicker 0.16em 不大写等）；mono = 抄 `body.theme-writer`（等宽标题、weight 500、tracking 0）
- `buildSlideTokens(style: ThemeStyle, preset): Record<string, string>` — 从提取结果派生品牌层令牌：
  - `--slide-title-font` ← `seedTypography.fontHeading`（确保含 CJK 回退并以 generic family 结尾，否则补 `"Noto Serif SC", serif` 类回退）
  - `--slide-mono` ← `seedTypography.fontCode`
  - `--slide-title-weight` ← `typography.headingWeight`
  - 其余令牌沿用预设值；字号阶梯不派生（版式比例不动，只换「声音」）
- 输出顺序稳定、每令牌一行，控制生成的 CSS 行数（模板现为 259 行，契约上限 300）

### 3. 数据模型与生成管线

- `src/models.ts`：`ThemeStyle` 增加可选字段 `slidePreset?: "serif" | "sans" | "mono"`（默认 undefined = 不生成 PPT 区块）
- `src/cli.ts`：`addExtractOptions` 增加 `.option("--ppt [style]", "Also emit PPT (--slide-*) style tokens; optional preset: serif|sans|mono", "serif")`；`runExtraction` 里设置 `style.slidePreset`（校验非法值报错退出）；`printSummary` 显示 PPT 预设
- `src/templates/theme-template.hbs`：SECTION 1 之后新增条件区块（约 30 行）：

```hbs
{{#if slidePreset}}
/* ═══ SECTION 1.5 — PPT / Slides（ColaMD 2.7.13 rc.2 幻灯片版式令牌）
   放映与导出 PDF（应用内）按这组 --slide-* 呈现；预设：{{slidePreset}}。
   完整令牌与 11 种版式见 colamd-themes skill 的幻灯片章节。 */
:root {
  ...buildSlideTokens 产物，每令牌一行...
}
{{/if}}
```

- `src/generator.ts`：模板上下文并入 `slidePreset` 与 `slideTokens`（调用 `buildSlideTokens`）；生成后自检链路不变（`validateThemeCss` 已能通过）

### 4. 校验规则：`src/validators.ts`

在 `validateThemeCss` 内（或抽 `validateSlideCss` 并入调用链）新增：

- **SLIDE-01（SHOULD）**：`--slide-*` 令牌名不在 `SLIDE_TOKENS` 清单 → 提示可能是拼写错误（rc.2 未知令牌会被 slides.css 忽略）
- **SLIDE-02（MUST_NOT）**：`.cm-md-page-*` / `.cm-md-slide-*` / `.slide-chrome` / `.slide-foot` / `.slide-ghost` 选择器**未**包裹在 `body.presenting` 或 `body.slides-printing` 作用域下（slides.css 全部规则只在这两个作用域生效；裸写会污染编辑视图）——`:root` 变量声明不受限
- **SLIDE-03（SHOULD）**：`--slide-title-font` / `--slide-serif` 栈须含 CJK 字族并以 generic family 结尾（沿用契约字体规则）
- `validate` 命令输出中追加幻灯片区块校验结果（有 `--slide-*` 时才显示）

### 5. Markdown → PPT Markdown：新建 `src/slides-markdown.ts` + CLI `to-slides`

- 新增依赖 `@lezer/markdown`（^1，上游同款解析器，devDependencies 与 dependencies 视打包方式定——mcp/dsh bundle 用 dist，放 **dependencies**）
- 模块内容：
  - `parsePages(md)`：HorizontalRule 分页（对齐上游 `pageOfLines` 语义：frontmatter 排除、`---` 归前一页）；HTMLBlock/CommentBlock 指令识别（对齐 `LAYOUT_RE`/`DECK_BLOCK_RE` 正则）
  - `inferLayouts(md)`：按页内容结构映射版式——
    - 首页 h1（+h2 副标题）→ `cover`；仅一个短标题 + 一段说明 → `section`
    - 有序列表 3-6 项 `**章名** 说明` → `agenda`；无序列表 2-6 项 `**数字+单位** 说明` → `kpi`
    - 列表项带年份/日期 → `timeline`；有序列表 3-5 项 `**步骤** 说明` → `steps`
    - 无序列表 3-8 项 `**名** 说明` → `matrix`；页面主体是图片/Mermaid/表格 → `figure`
    - blockquote 页 → `quote`；恰好两个 h2 对半 → `two-col`；末页清单 → `closing`；其余 → 不写 slide 块（默认文章版式）
  - 生成 deck 块（来源优先级：CLI 选项 > frontmatter title > 文档首个 h1）
  - 每页页头块：`<!-- slide: 版式` + `kicker`（章节名/自动摘取）+ `label`（缺省 deck-title）+ `chapter`（章节推进）+ `-->`
  - `validateSlidesMarkdown(md): ValidationIssue[]` — 版式名符合 `^[a-z][a-z0-9-]*$`（未知名 WARN）、字段键 ∈ kicker/label/chapter、deck 键 ∈ logo/brand/title/meta、slide 块必须在页首（页第一个真实内容之前）、`slide-css` 值不含 `position: absolute/fixed` / `z-index` / 伪协议（对齐上游 `scopeSlideCSS` 白名单精神）
- CLI（`src/cli.ts` 注册）：`to-slides <input.md> -o <output.md> [--deck-brand] [--deck-title] [--deck-meta] [--deck-logo]`；生成后自动跑 `validateSlidesMarkdown` 并汇报
- `validate` 命令扩展：参数接受 `.md` 文件时改跑 `validateSlidesMarkdown`（CSS 文件走原逻辑）
